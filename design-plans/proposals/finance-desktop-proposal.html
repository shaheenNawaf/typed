Proposal · Desktop Finance Workspace

Finance takes the whole canvas

Audited live against the current build at 1440×900 (finance tab, seed data, Cream/dark palette). Three directions, one recommendation, and a full-fidelity prototype of it. Everything maps onto existing AppColors/AppMetrics tokens — no new primitives, no new accent.

01 What the current build shows

Observed on the running app (1440×900), cross-checked against the discovery evidence in design-plans/05 and 07.
F1 · WIDTH
The note-list pane squats on a third of the canvas.

With Finance active, a ~340 px pane renders one truncated card (“Quick expenses — … Net ₱14,820.00 · 2 e…”) and ~85 % empty space, while the dashboard itself is capped at 1080 px (≈820 px actually used). The monthly ledger note is an implementation detail of capture — it doesn't earn prime left real estate.

F2 · DEAD CARDS
Two stat slots go dark at the default scope.

“Avg daily spend” renders an em-dash whenever the period is All-time (no denominator), and the 14-day sparkline is squeezed into a flex:2 corner of a 4-up row where sparse data reads as broken (one bar + a dashed baseline).

F3 · FLAT HIERARCHY
Six boxes of equal weight; no hero.

Income / Expenses / Net / Transactions / Saved / Avg all render at the same visual rank. The one number the workspace exists to answer — what's left — is the same size as its inputs, and the savings rate is a t12 footnote.

F4 · DEAD ZONE
The layout stops at ~60 % height.

The workspace is a top-anchored card stack; below the budgets block, ~340 px of the viewport is empty at 1440×900. The 05 evidence (E7, E12, E13 — caps, no visualization) is partly addressed; the composition still ends too early.

02 Three directions

All three keep the existing token system, the sidebar, the capture buttons and the honesty rules from proposal 05.

A — Full-canvas workspace

Recommended

Drop the note-list pane when Finance is active; the workspace spans the content width. Hero Net + promoted full-width trend + day-grouped ledger + compact right rail.

  • Biggest visibility win; kills F1–F4 in one move
  • Layout branching only — no new widgets beyond a trend card
  • List pane stays for Notes / Tasks / Archive

B — Dense ledger

Alternative

Power-user shape: fixed summary rail (net, budgets, categories) + a full flat ledger table with per-column sorting and inline filters.

  • Best for heavy entry volumes (50+/month)
  • Reads like a database report — the exact register proposal 07 pushes away from
  • Highest build cost (table semantics, sort state)

C — Chart-digest

Alternative

Trend as the centerpiece (calendar heat-strip + 30-day curve), transactions collapse into a "recent" strip below. Most glanceable, least list-first.

  • Strong first impression
  • Weak for the actual job: reviewing/editing entries
  • Calendar strip needs a custom painter

03 Recommended — Option A, full prototype

1440-wide canvas at 80 %, shown at full scroll height. Sample fixture: September 2026, PHP-dominant with one USD entry (honesty footnote), three budgets in three states. Numbered badges map to the change legend below.

5Day-grouped ledger with signed amounts. Today / Yesterday / weekday headers, −/+ signed values (color is secondary, per 05-D), per-row entry edit on hover, uncapped “View all” (E8/E12).
6Budgets that tell the truth + proportional categories. Over-budget fills the bar and states the overshoot (E2's clamp is gone), amber for 81 %, quiet green on-track state (07-D3); category share visible as fill, not just text (07-D2).
