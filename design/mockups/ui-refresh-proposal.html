01The logo problem

The current logo is a <text> element that depends on a remote Google Fonts import. Inside Flutter, flutter_svg can't resolve it — the mark renders with a fallback font (or nothing when offline). It's also a different shade of red (#E53E3E) from the brand accent (#CC4D3C), and the app has a second, blocky mark via the CustomPainter. Three logos, no consistency.

  • Broken render path: typed-logo-dm-sans.svg needs the DM Sans webfont; flutter_svg doesn't load remote CSS → unpredictable glyph rendering in-app and in the README depending on network/fonts.
  • Two different marks: the painter in brand_mark.dart is a geometric block-t., the SVG is a font-t. — they never look like the same brand.
  • Painter bug: the crossbar is painted charcoal, but BRANDING.md §1 says crossbar = accent red.
  • Wrong red: SVG uses #E53E3E instead of #CC4D3C.

02Proposed mark — one geometry, everywhere

A single path-based mark (no font dependency): a lowercase t with an overshooting accent crossbar and a square accent period on the baseline. Same 64-unit geometry drives the SVG, the Flutter painter, and the Android vector — so every surface matches exactly. Slightly softened corners (1px radius) keep it typographic rather than LEGO.

03App UI — sidebar & workspace
